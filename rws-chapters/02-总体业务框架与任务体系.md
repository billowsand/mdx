## 第二章 总体业务框架与任务体系

### 2.1 战略层面认知攻防作业闭环

总体业务框架以"感知—筹划—评估"为主线，围绕**常态塑势（主动谋局）**与**危机应对（事件处置）**两类典型场景展开，服务于战役层面和战略层面的指挥筹划单元。当指挥筹划单元受领事件处置或主动谋局任务后，依托态势感知产品与筹划分析工具，完成一个从认知场感知到认知场影响、再回到认知场感知的完整闭环：

1. **受领任务并明确任务意图**：明确任务目标、重点对象、地域范围、时间窗口、优先信息需求和行动约束；
2. **意图驱动采集与监测核验**：按照任务意图组织信息采集，持续发现疑似虚假信息和异常传播线索，开展多源核验并保留不确定性；
3. **态势、叙事与对手意图研判**：分析事实、主体、传播链、内容变体和竞争性叙事，以竞争性假设方式研判对手可能意图，明确支撑证据、反对证据和信息缺口；
4. **威胁分级与筹划成案**：依据真实性、传播性、影响范围、任务关联度和紧迫性开展威胁分级，形成法理、口径、措施、产品和任务相衔接的反制方案；
5. **方案评估、可执行性推演与决策**：从计划、调查、组织资源、行动协调和评价准备等方面评估方案，推演组织协调、资源投入、任务依赖、审批链、时序安排和叙事协同，修改完善后按程序呈报决策；
6. **行动实施与闭环再感知**：相关任务行动单元依令实施，感知系统同步监测资源、传播和叙事变化，支撑动态调整；
7. **事后评估与知识沉淀**：对照方案基线、推演发现和实际执行情况复盘，形成整改任务并推动理论、数据、算法、工作流和平台迭代。

这一闭环的两端都落在认知场资源上：感知端观测资源动态、研判态势，行动端影响资源状态、达成认知目标，评估端度量资源变化、校验目标达成，形成"感知—影响—再感知"的螺旋上升。系统的价值，就在于对闭环各关键环节提供支撑，研制任务据此定义（见2.3）。

### 2.2 闭环各阶段作业

#### 2.2.1 态势感知

指挥筹划单元受领任务后，首先利用系统获取整个认知场相关资源的动态。资源来源分为两侧：

- **互联网侧（主）：** 数据中心、网络链路、社交平台、媒体网站、社交账号、官方声明、政策法规等公开可获取信息；
- **内部侧（辅）：** 从相关任务单元和职能部门获取的内部辅助信息。

在资源动态基础上，系统首先区分**任务意图**与**对手意图**。任务意图由我方任务目标转化而来，用于确定优先信息需求、观测指标、来源优先级和采集节奏；对手意图是对外部主体行动目的的分析判断，应以多种竞争性假设表达，并持续以支撑证据、反对证据和新增信息进行更新。系统同步支撑疑似虚假信息发现、内容核验、传播链与叙事分析、威胁分级，形成认知场态势研判。感知阶段按触发方式分为两类场景：

- **常态塑势（主动谋局）：** 以长期任务意图和重点方向为牵引，持续开展信息需求管理、任务意图驱动采集、数据治理、趋势监测、议题发现、疑似虚假信息监测、多事件关联、叙事与对手意图研判和知识更新，主动形成重点问题、态势变化、风险机会、研究选题和筹划启动建议；
- **危机应对（事件处置）：** 由突发事件、风险告警、疑似虚假信息异常传播或上级指令触发，快速完成线索核验、扩展采集、内容变体归并、传播与叙事分析、多事件关联、人物组织和地域识别、对手意图研判、威胁分级及数据完整性说明，形成危机态势快报、关键问题和紧急筹划需求。

#### 2.2.2 筹划分析

态势研判形成后，进入基于感知结果的深度研究与筹划。筹划分析的核心产出是一份可实施方案，其主要内容包括：

1. **相关措施和任务的拟制** —— 针对认知目标提出可落地的行动措施，并分解为可执行任务；
2. **口径和信息产品的拟制** —— 面向不同对象和渠道形成一致、准确、可审定的口径与信息产品；
3. **与认知攻防相关的信息** —— 生成支撑行动所需的法理依据、背景知识、对象研究等认知攻防要素。

为保证方案质量，筹划按以下研究生产链组织：问题定义，事实、态势与对手意图研判，法理研判，口径拟制，分级反制方案生成，产品清单、任务筹划与任务分配，评价基线，成果审定。各环节依次衔接、逐环受控；对核验不足的疑似虚假信息，不得以确定性结论进入对外口径和行动任务。

深度研究的输出不是单一报告，而是由综合研判成果、法理成果、口径成果、方案成果、产品清单、任务分配、任务计划、证据与数据包、评价基线组成的筹划成果包。

#### 2.2.3 方案评估、推演与决策

可实施方案形成后，须经校核、完善与决策方可实施：

1. **方案评估与可执行性推演：** 在下达前从计划完整性、调查充分性、组织资源准备度、行动设计协调性、评价设计可行性五个方面评价备选方案；围绕组织协调、资源投入、任务依赖、关键路径、审批链、时序冲突、叙事冲突和替代路径开展执行过程推演，据此修改完善。推演不承担舆情走势和对手行为结果预测；
2. **征求意见与呈报：** 完善后的方案征求相关职能部门意见、进一步完善，再呈报相关领导，由指挥员下达行动命令；
3. **事后评估：** 在实施后评价目标达成、产品质量、任务履行、资源投入、实际效果和风险，形成整改与能力迭代任务。

#### 2.2.4 行动实施与闭环再感知

指挥员下达行动命令后，由相关任务行动单元实施具体行动。行动的本质是对认知场资源的有目的影响——通过改变数据中心、网络链路、社交平台、社交账号、官方声明等资源的状态，最终实现认知攻防目标。在行动过程中，态势感知产品同步评估相关资源的变化情况，基于行动单元回传数据和感知监测开展动态评估，支撑指挥筹划单元调整后续行动，从而闭合一个战略层面的作业回路。此处的"再感知"是行动过程中的实时监测、服务于即时调整，区别于行动结束后对目标达成与实际效果的系统复盘（事后评估，见2.2.3）。

#### 2.2.5 系统支撑环节与任务映射

闭环各环节的系统支撑，直接定义了研制任务，按"感知—筹划—评估"三段对应四类任务：

- **态势感知段**（任务意图 → 信息采集 → 数据治理 → 单/多事件分析 → 虚假信息核验与威胁研判）：常态与危机双场景入口及各研判环节，对应 **GZ-01～GZ-07**；
- **筹划分析段**（研究组织 → 事实法理 → 口径方案 → 产品任务）：可实施方案的成案链路，对应 **CH-01～CH-06**；
- **评估决策段**（方案评估 → 可执行性推演 → 实施后复盘）：方案校核与闭环反馈，对应 **PG-01～PG-03**；
- **贯穿全程的保障**（工作流、知识、数据模型、总体集成）：对应 **ZC-01～ZC-04**。

### 2.3 任务体系

全部研制任务依业务闭环分为感知（GZ）、筹划（CH）、评估（PG）三类核心任务和共性支撑（ZC）一类保障任务，共20项。每项任务的四类支撑——作战理论、关键算法模型、系统平台、数据——分别由ZZXQ-1（作战理论研究）、XJJS-8（先进算法技术研制）、对应系统研制单位、SJZLTD（数据治理）承研；对应系统研制单位同时担任该任务总体集成单位，负责将各类支撑成果集成为可运行能力并对结果负责：感知类由TSXZ-3承担，筹划与评估类由ZZXZ-4承担，共性支撑类由TPHJ-6承担，全项目总体集成由ZTSJB指导承担。其中，感知、筹划、评估类任务（GZ、CH、PG）具备完整四类支撑；共性支撑类任务（ZC）不含作战理论支撑，相应不承担作战理论支撑课题。

### 2.4 核心术语释义表

本表对贯穿全文的高频术语作业务化释义，供业务部门与技术部门统一理解；术语首次出现时也可回查本表。

| 术语 | 业务释义 | 场景举例 |
|------|---------|---------|
| 认知场 | 承载认知形成与传播的资源集合。对外为互联网侧的数据中心、链路、平台、账号、声明、法规等；对内为各任务与职能部门掌握的相关信息 | 围绕某议题，X平台上一批账号、帖文、转发链和境外媒体的报道共同构成一个"认知场" |
| 任务意图 | 我方任务目标转化而来的采集与分析导向，决定优先看什么、看多快、看哪里 | 任务目标"稳住涉疆舆论态势" → 任务意图包含优先信息需求、观测指标、来源优先级 |
| 对手意图 | 对外部主体行动目的的研判判断。须以多种竞争性假设表达，并随证据更新 | 对手集中投放某虚假视频，假设A：转移对我议题注意力；假设B：为后续行动铺垫情绪 |
| 竞争性假设 | 同时保留多种可能解释，分别列明支撑证据、反对证据和信息缺口，避免单一归因 | 对同一传播异常同时保留"对手主动推动"和"算法自然放大"两个假设，分别验证 |
| 支撑证据/反对证据/信息缺口 | 假设论证的三件套：支持该假设的证据、削弱该假设的证据、尚缺的关键信息 | 假设A的支撑证据：账号集中注册时间；反对证据：无统一文案模板；信息缺口：账号背后主体未识别 |
| 内容变体 | 同一原始信息在传播中被改写、改图、剪辑、翻译后形成的不同版本 | 一段虚假视频衍生出"亲历版""证据版""中英对照版"等十余个变体 |
| 叙事 / 竞争性叙事 | 叙事是对事件因果与意义的整体讲述框架；竞争性叙事指不同主体讲述同一事件时相互争夺主导权的多套叙事 | 围绕同一事件，"受害者叙事"与"依法处置叙事"并行竞争受众认同 |
| 传播链 | 信息从首发到扩散所经过的账号、平台、时间、互动等节点序列，用于识别关键放大点和异常 | 某帖由境外账号首发→3个KOL转发→2个境内账号搬运，形成可追溯链 |
| 威胁分级 | 依据真实性、传播性、影响范围、任务关联度和紧迫性对疑似虚假信息给出的处置优先级 | 高威胁（48小时限期）：真伪已核、跨境联动、影响特定议程 |
| 异常放大 | 传播曲线显著偏离同话题基线，往往指向协调行为或平台机制被利用 | 某帖2小时内互动量达同类10倍，账号集中度异常 |
| 五方面评估 | 方案下达前/后统一从计划完整性、调查充分性、组织资源准备度、行动设计协调性、评价设计可行性五个维度评价 | 计划完整性：是否漏排里程碑；组织资源准备度：牵头单位能力是否到位 |
| 可执行性推演 | 按实际执行链路对方案做过程仿真，预查组织协调、资源、任务依赖、审批、时序、叙事冲突等问题；不预测舆情走势或对手行为结果 | 推演发现：某环节审批阻塞，调整审批顺序后回放验证消除 |
| 事后评估 | 行动实施后对照方案基线、推演发现和实际执行复盘，区分方案问题、执行问题和外部环境变化 | 复盘发现实际效果偏差主因是外部平台规则变化，而非方案设计问题 |
| 情报六要素 | who、what、when、where、why、how 六个基本情报要素，用于结构化采集任务和事件描述 | 采集任务要求：谁发布、发了什么、何时、何地平台、为何、如何扩散 |
| 在地化变体 | 同一信息在不同地区/语种下的本地化措辞、称呼、语境适配版本 | 同一话题在东南亚和欧洲的 hashtag、用语习惯不同，采集规则需分别生成 |
| 知识沉淀 | 将研判结论、变体、传播链、叙事、意图假设、推演问题等编译为可审核、可引用、可演化的知识页面 | 本轮核验结论入库后，下一轮相似线索可直接检索复用，不必从零核验 |
| 口径 | 面向不同对象和渠道、经审定的一致表述，含核心立场、事实澄清、问答口径、对象化表述等 | 同一事件对内通报口径、对外发布口径、对特定受众解释口径在事实和立场上须互通 |

### 2.5 典型场景贯穿示例

下面以我与菲律宾在仁爱礁问题上的认知攻防为例，依次走完"感知—筹划—评估"全闭环，说明系统在每个环节支撑了什么、人工决定了什么，作为全文的导航地图。示例涉及的具体时间、账号、数据均为示意性描述，非实指。

**情境：** 菲方某次向仁爱礁"坐滩"军舰运补期间，境外社交平台集中出现一批所谓"现场目击"帖文和视频，声称我方对菲方运补船只"过度拦截""危及人员安全"，有关内容在数小时内被多家西方媒体转载，并出现英文、日文、越南语等多语种版本，互动量快速攀升。

**1. 受领任务并明确任务意图（人工）。** 指挥筹划单元受领处置任务，明确任务目标"还原事实、稳住态势、压缩虚假叙事跨境扩散"，重点对象为国际舆论受众与南海周边国家受众，时间窗口以事件热度周期为准，优先信息需求为"首发信源身份与地理归属、多语种扩散路径、是否协调行为、与以往类似议题叙事模板的关联"，行动约束为"对外口径须经审定、不主动升级叙事"。

**2. 意图驱动采集与监测核验（系统+人工）。** 系统按任务意图自动生成优先信息需求、观测指标、来源优先级和采集关键词（含英文、菲律宾语、越南语、日语等在地化变体及" water cannon""blockade""Ayungin"等关键词），人工确认后下发；系统持续采集相关帖文、跟帖、互动数据和视频元数据，并标注数据完整性。系统自动将"过度拦截""危及人员安全"等未经核验的指控统一标注为"疑似虚假信息"，提示人工审定，不得以系统结论直接定性。

**3. 多源核验与传播叙事分析（系统支撑，人工拍板）。** 系统跨来源比对：发现部分视频存在剪辑和画面拼接痕迹，与我方公开的现场执法记录和权威通报冲突；归并出十余个内容变体（"被撞翻版""水炮伤人版""舰船对峙版"等）；重建传播链，识别出3个关键放大账号、1个异常集中发帖时段和疑似协调行为特征。系统以竞争性假设方式同时列出两种对手意图——假设A：菲方为运补行动造势、争取国际同情（支撑证据：发帖时间与运补时间重合、菲官方账号率先转发；反对证据：暂未发现菲政府直接组织痕迹；信息缺口：首发账号背后主体未识别）；假设B：第三方借机嵌入"中国威胁南海航行自由"的长期叙事（支撑证据：西方智库账号快速接入、套用以往南海议题话术模板；反对证据：暂缺）。授权人员审定最终定性为"部分内容已证伪、部分证据不足"。

**4. 威胁分级与筹划成案（系统建议，人工决策）。** 系统按真实性、传播性、影响范围、任务关联度和紧迫性给出威胁等级——该批内容跨境联动明显、已影响南海议题议程、紧迫性高，建议48小时限期处置。进入筹划后，沿问题定义→事实态势研判→法理研判→口径拟制→方案生成→产品任务链逐环产出：法理研判调取《联合国海洋法公约》有关条款、我方历史立场和仲裁裁决立场材料；口径拟制形成对外权威通报口径、问答口径和面向南海周边国家的对象化表述；方案生成输出2套分级反制备选方案——方案一侧重"权威事实+现场视频对冲+外交口径同步"，方案二在方案一基础上增加"组织专家解读+南海周边国家定向沟通"。系统不自动选定最终方案。

**5. 方案评估、可执行性推演与决策（系统校核，人工决策）。** 系统从计划完整性、调查充分性、组织资源准备度、行动设计协调性、评价设计可行性五个方面对两套方案做评估，识别"方案二定向沟通环节牵头单位资源峰值冲突"等缺项；可执行性推演进一步发现"24小时窗口内对冲发布与定向沟通两步骤审批链阻塞，且口径发布与外交表态时序存在叙事冲突风险"，给出"对冲发布前置、定向沟通后置并错峰审批"的替代路径。人工据修改完善方案，按程序呈报决策。指挥员下达行动命令。

**6. 行动实施与闭环再感知（行动单元实施，系统监测）。** 行动单元依令发布审定口径和现场对冲素材、协调外交表态、推送权威信息至目标平台和受众；系统在行动过程中同步监测互动量、转发链、叙事变化，标注异常未消的节点和新增内容变体，支撑是否加推一批口径或追加证据披露的动态判断。

**7. 事后评估与知识沉淀（系统复盘，人工定责）。** 行动结束后，系统按五方面对照方案基线、推演发现和实际执行复盘，区分"方案二定向沟通预留时间不足（方案问题）""某平台对涉我内容限流规则临时收紧（外部环境变化）""现场对冲素材人工审定延迟4小时（执行问题）"，形成3条整改任务与2条知识更新项；本轮核验结论、内容变体簇、传播链、对手意图假设、法理口径素材和叙事模板编译入库，下一轮遇到类似仁爱礁议题或南海其他摩擦时可直接检索复用，启动新一轮"感知—影响—再感知"螺旋。

**贯穿要点：** 任务意图始终牵引采集与研判；疑似虚假信息未经授权不得定性为虚假；对手意图始终保留竞争性假设；关键结论以证据三件套（支撑/反对/缺口）留痕；方案、产品、任务一一可追溯；系统全程在闭环各关键环节提供智能建议，人工决定采集下发、定性、口径审定、方案选定、任务下达和事后定责。
