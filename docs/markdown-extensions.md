# mdx Markdown 扩展标记使用说明

本文档约定使用 mdx 工具（`mdx docx|tex --style official|research`）转换时，
markdown 源文件应遵循的写法。除标准 GFM 子集外，mdx 支持若干扩展标记；
按本说明撰写可保证 docx / tex 输出结构、编号、图片引用正确。

## 1. 标题层级

| markdown | official（公文） | research（研究报告） |
|---|---|---|
| `#` | 红头大标题（居中、小标宋二号） | 文档标题（封面；每个输入仅取第一个 H1） |
| `##` | 一、二、三…（黑体） | 第 X 章（`\chapter`，拆分为 `data/chapterNN.tex`） |
| `###` | （一）（二）…（楷体） | X.Y（`\section`） |
| `####` | 1. 2. 3. | X.Y.Z（`\subsection`） |
| `#####` | (1) (2) (3)（粗体） | `\subsubsection` |
| `######` | 忽略 | 忽略 |

- 标题中的旧编号（`一、`、`1.1`、`（一）`、`第X章` 等）会被自动剥除，编号由输出端
  自动生成，**不要在标题里手写编号**。
- research 附录段内：以 `#` 开章则 `# → chapter`、`## → section`；不用 `#` 时
  `## → chapter`（与正文一致）。一份文档内建议统一一种写法。

## 2. 封面字段（research，front matter）

文件**首行**起用 `---` 包围的 `键: 值` 行会被解析为封面字段（冒号中英文均可）：

```markdown
---
密级: 机密
年限: 5年
文件类型: 技术报告
文件编号: XX-2026-001
文件版本号: V1.0
撰写单位: 某研究所
撰写时间: 2026-07
文件名称: ××系统研制报告
---
```

- 支持的键：`密级`、`年限`/`保密年限`/`保密期限`、`文件类型`/`类型`、
  `文件编号`/`编号`、`文件版本号`/`版本`、`撰写单位`/`单位`、
  `撰写时间`/`时间`/`日期`、`文件名称`/`标题`（亦接受英文键名）。
- `密级` 与 `年限` 是两个独立字段，封面上以五角星连接排为 `密级：机密★5年`
  （tex 用 pifont 的 `\ding{72}`）。只写 `密级` 时不出现星号；`年限` 按原文
  输出，请自带单位（写 `5年` 而非 `5`）。
- `撰写时间` 支持 `2026-07` / `2026/7` / `2026.07` / `2026年7月`，输出统一为
  "YYYY 年 M 月"；缺省取编译当月。
- 未闭合的 `---` 不视为 front matter。封面字段仅在 research 路径生效；
  `bibliography` 字段由两种 tex 样式共同读取。

## 3. 区段标记（research）

行内 HTML 注释切换文档区段，独占一行：

```markdown
<!-- [摘要] -->            进入摘要段（内容汇入 abstract 环境）
<!-- [正文] -->            回到正文（章节计数重置）
<!-- [附录] -->            进入附录段（\appendix，章节拆到 appendix/appendixNN.tex）
<!-- [版本变更记录] -->     版本变更记录（不编号，\chapter*）
<!-- [参考文献] -->        参考文献（不编号，列表项自动加 [1] [2] 前缀）
```

- 摘要、版本变更记录、参考文献内容始终保留在主 tex 文件；正文各章、附录各章
  分别拆分到 `data/`、`appendix/` 子文件。
- official 路径忽略这些标记。
- BibTeX 自动引用不需要 `<!-- [参考文献] -->` 标记；该标记仍可用于手写参考文献段。

## 5. 交叉引用（`tex`，编号锚点与引用）

在被引用对象尾部加 `{#id}` 打锚点，正文里用 `{@id}` 引用，tex 编译为
`\label{id}` / `\ref{id}`，编号由 LaTeX 计数器自动生成，章节/图/表调整顺序
后引用自动跟随。

```markdown
## 第一章 概述 {#chap:overview}

![系统架构图](pics/arch.png){#fig:arch}


| 名称 | 数量 |
|------|------|
：产品清单 {#tbl:products}

详细方法见第{@chap:method}章，架构如图{@fig:arch}所示，清单见表{@tbl:products}。
```

- **锚点位置**：标题行尾部（章/节均可）、图片 `![...](...)` 后紧跟、表题行尾部。
- **引用写法**：`{@id}`，中文措辞（"第 X 章 / 图 X / 表 X"）由作者围绕引用书写，
  `\ref` 只输出编号。
- **id 规则**：字母开头，可含字母、数字、`:`、`.`、`_`、`-`；建议用
  `chap:` / `sec:` / `fig:` / `tbl:` 前缀分类（约定，不强制）。
- **生效范围**：research 完整支持（章、节、图、表）；official 支持图片与表格
  锚点（章节无自动编号，标题锚点被忽略）；docx 暂不支持，引用降级为 id 文本。
- **前提条件**：图引用需要替代文本（作为 `\caption`，无 caption 不输出 `\label`）；
  表引用需要表题（无表题时表格计数器不递增，引用无意义）。
- **转换前检查**：tex 转换会先校验全部锚点与引用，存在以下硬错误时逐条列出并
  **停止转换**（不产生任何 tex/PDF 输出）：
  - `{@id}` 引用了未定义（或在当前样式下不生效）的锚点；
  - 同一锚点重复定义；
  - 锚点不会生效：未挂接到标题/表格、图片缺替代文本、图片未独占一段、
    official 样式下的章节锚点。

  锚点已定义但未被引用仅打印警告，不停止转换。

## 6. 文献引用（tex）

文档开头用 front matter 声明一个 BibTeX 文件：

```markdown
---
bibliography: refs/library.bib
---

已有研究给出了相同结论 [@zhang2024]。
两种方法可结合使用 [@li2023; @wang2022]。
```

- Bib 路径相对于单文件输入所在目录；目录输入时相对于输入目录。
- `[@key]` 输出 `\cite{key}`，`[@a; @b]` 输出 `\cite{a,b}`。
- 支持段落、列表项和表格单元格；标题、行内代码和 fenced code block 不解析 citation。
- 只支持一个 Bib 文件和上述两种方括号形式；不支持裸 `@key`、`[-@key]`、页码、
  前后缀或多个 Bib 文件。
- research 与 official tex 都使用 `biblatex` 的 `gb7714-2015` 样式；Docx 不生成
  Word 原生 citation，保留 `[@key]` 原标记。
- 转换前会严格检查 Bib 文件。以下情况为硬错误并停止转换：
  - 正文有 citation，但 front matter 未声明 `bibliography`；
  - Bib 路径不存在、不是文件或无法读取；
  - BibTeX 格式错误或存在重复 key；
  - citation key 在 Bib 中不存在。
- 声明了 Bib 时，即使正文没有 citation 也会检查文件；Bib 中未引用的条目不报错。
- 校验成功且正文有 citation 时，Bib 被复制到 tex 输出目录并命名为
  `references.bib`。参考文献表只列出实际引用的条目。

## 7. 表格与表题

GFM 管道表格：

```markdown

| 列A | 列B |
|-----|-----|
| 1   | 2   |
：产品清单 {#tbl:products}
```

- 表题写法（三选一）：表前一行 `Table: 标题` / `表: 标题` / `表：标题`，或表后
  一行 `: 标题`。带编号的写法（`表1：标题`、`Table 1: 标题`）也可识别，**编号会
  被剥除**，由 LaTeX 计数器自动生成，请勿手写编号。
- research 与 official 都输出 `longtblr`（tabularray 智能表格：自动分析内容
  决定对齐方式与列宽，窄数字列固定 2em；单元格支持 `**粗体**`、`*斜体*`，
  脚注降级为全角括号内联注释），表题编号由 LaTeX 计数器自动生成，
  `{#tbl:id}` 锚点均可在正文中用 `{@id}` 引用。两者都可跨页断开、表头在
  续页重复：紧缩排版下不会为了"整表完整显示"把表推到下一页。

## 8. 行内格式

| 写法 | 输出 |
|---|---|
| `**加粗**` | 粗体（至少 4 字符才识别） |
| `*斜体*` | 斜体（中文以楷体表达） |
| `` `代码` `` | 等宽 |
| `[文字](url)` | tex：`\href`；docx：纯文字 |
| `[^id]:(注释内容)` | 行内脚注，编号自动生成；冒号、括号兼容全角 |

- 裸 `[^id]`（无 `:(内容)`）不识别，按普通文字输出。
- 中英文直引号会全局正规化为中文圆引号；代码块内保持原样。

## 9. 列表

```markdown
- 无序项
* 亦可
1. 有序项
```

- 每行一个列表项；编号前缀由输出端按层级循环生成，不要手写编号。
- 层级由前导空白推断：0 → 1 级，1–4 空格 → 2 级，5–8 → 3 级，9–12 → 4 级，
  13–16 → 5 级，更多 → 6 级。
- official 前缀循环：①②③ → ⑴⑵⑶ → a.b.c. → I.II.III. → (A)(B) → 1)2)；
  research 前缀循环：1. 2. 3. → (1) (2) → a. b. → I. II. → (A) (B) → 1) 2)。

## 10. 代码块

````markdown
```rust
fn main() {}
```
````

- 信息串第一个词作为语言（research tex 映射到 listings 语言；未知语言按纯文本）。
- official tex 暂不支持代码块（忽略）。

## 11. 目录输入合并

`mdx ... <目录>` 时按**文件名升序**合并目录顶层所有 `.md`（建议用
`01-xxx.md`、`02-xxx.md` 命名控制顺序）。research 路径取第一个 `# 标题` 作为
文档标题并从正文移除，并自动剥离每个文件的 UTF-8 BOM。

## 12. 明确不支持的语法

数学公式、引用式脚注（`[^id]` + 单独定义行）、blockquote、raw LaTeX/HTML、
嵌套/多段落列表、复杂表格、完整 inline 嵌套。请勿在源文件中使用，输出不可预期。
